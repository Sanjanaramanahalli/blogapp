🎯 The Problem & Vision

Modern Web Dilemma: Over-Engineering vs. Reliability

Why traditional full-stack publishing applications fail at scale and maintainability.

❌ Common Industry Pitfalls

  • Massive 500KB+ frontend JavaScript client bundles slowing down initial render.
  • Orphaned database records when deleting articles or parent comments without foreign key constraints.
  • Fragile like counters vulnerable to race conditions and duplicate increments.
  • Monolithic or leaky access control where readers can hijack others' articles.

✅ The ApexBlog Solution

  • Zero-framework Vanilla core delivering instant LCP (Largest Contentful Paint).
  • Strict SQLite ON DELETE CASCADE guarantees zero orphaned comments or likes.
  • Database-enforced UNIQUE(blog_id, user_id) provides idempotent binary likes.
  • Comprehensive RBAC & Author Ownership middleware enforcing least-privilege security.

🗄️ Database Architecture

Relational Schema & Referential Integrity

Normalized relational model engineered for zero data leaks.

Table Primary Key Key Foreign Constraints Cascade Behavior
users id (INTEGER) — (Email unique index) Deleting user cascades comments & likes
blogs id (INTEGER) author_id REFERENCES users(id) Deleting blog cascades all comments, likes, tags, categories
comments id (INTEGER) blog_id REFERENCES blogs(id), parent_id REFERENCES comments(id) Deleting comment cascades all child replies down tree
likes id (INTEGER) blog_id, user_id (UNIQUE constraint) Guarantees strictly 1 like per user per blog
